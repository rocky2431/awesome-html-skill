awesome-html：页面发出去为什么还能打开

因为交付前，页面已经被做成一个什么都不缺的文件，并且被检查过。页面契约规定它只能是一个 .html；inline.py 把它引用的本地文件写进去；check.py 先扫描标签里有没有向外的引用，再在断网的 Chrome 里用两种宽度、两种配色打开它，把每次渲染切成 1200px 高的截图交给 agent 逐块看。

每节末尾列出处。SKILL.md、scripts/、references/、assets/ 在 skill 目录 plugins/awesome-html/skills/awesome-html/ 下，其余文件在仓库根目录。终端输出是 2026-10-06 在本机实际运行的结果，演示文件在临时目录，命令和路径缩短成了 scripts/… 和 demo/…。

两条进路，落到同一个文件

写页面时可以照常引用本地文件，比如 skill 自带的 Chart.js、一张图片、一个字体文件。进度看板不手写，由 track.py 从仓库里的 Markdown 文件生成。两条路最后都得到一个 .html 文件，再交给 check.py。有 ✗ 就改页面、从头再跑；没有 ✗、截图都看过，才把文件发出去。

SKILL.md 把这件事写成七步，agent 按顺序做：

  1. 定需求：读者、页面类型、力度、精度。
  2. 找项目已有的设计语言，照着用。
  3. 先写 :root token，对照主题审一遍。
  4. 复制起始模板，替换占位内容。
  5. 有本地引用时，跑 inline.py。
  6. 跑 check.py，修 ✗，看每块截图。
  7. 交付：路径、内容、检查结果、没验证的部分。

出处SKILL.md「Workflow」；README.md「How a page is made」；references/track.md「Source of truth」

页面契约：什么样的页面算“能发出去”

契约写在 SKILL.md 的「Contract for every page」，每个页面都要满足这七条。离线、宽度和 file:// 三条由 check.py 机械检查，缺 <title> 时它也会提醒；其余的靠 agent 在交付前对照 references/checklist.md 逐项核对、看截图。

规则要求谁来保证
一个文件，全部在内 CSS 写在 <style>，JS 写在 <script>，图片和字体用 data: URI，图用内联 SVG。不用 CDN 脚本、web 字体、远程图片。向外的 <a> 链接可以。 inline.py 写进来；check.py 静态扫描报 ✗，渲染时发出的请求也报 ✗
位置 用户指定的路径；否则是项目根目录下的 html/<slug>.html；在项目外或 ~/.claude 这类配置目录里时，用 ~/awesome-html/<slug>.html。不主动提交生成的页面。 agent 自己遵守，脚本不查
标题和语言 <title> 是短名称：两到四个英文词，或约 4 到 10 个汉字。<html lang> 和内容一致，中文用 zh-CN。 缺 <title> 时 check.py 报 !；lang 由 agent 对照清单检查
主题 颜色写成 :root 上的 token；在 prefers-color-scheme: dark 下有专门设计的深色主题。 check.py 浅色、深色都截图，agent 逐块看
宽度 400px 宽时不能横向滚动。 check.py 在 400 和 1280 宽下检测，横向滚动报 ✗
file:// 规则 fetch() 读不了本地文件，数据嵌进 <script type="application/json">。不用 ES module 导入别的文件。history.* 和 localStorage 包在 try/catch 里。 check.py 用 file:// 打开页面，JS 异常和 console.error 报 ✗
内容诚实 用读者的词。样例数据标明是样例。不编造指标、引语和来源。 agent 自己遵守，见 references/explain.md 和 checklist.md

出处SKILL.md「Contract for every page」；references/checklist.md；scripts/check.py

inline.py：把本地文件写进页面

页面引用了本地文件时，inline.py 把它们换成文件里的内容。只要有一个文件找不到，它就整个停下、什么都不写，不留半成品。

  • <script src="x.js"></script> 变成带 data-inlined="x.js" 的内联脚本；脚本里的 </script 被转义，不会提前结束标签。
  • <link rel="stylesheet"> 变成 <style data-inlined>；本地的 <link rel="icon"> 变成 data: URI。
  • img、source、video、audio、track 和 SVG image 上的 src、srcset、poster、href 变成 data: URI。
  • <style>、style="" 和被内联的 CSS 里的 url() 与 @import 也一并写进来。

找文件的顺序：先找引用它的文件所在目录（CSS 里的引用按那个 CSS 文件的目录算），再找页面所在目录，最后找 skill 的 assets/。所以任何页面都可以写 vendor/chart.umd.min.js，它会解析到 skill 自带的 Chart.js 4.5.1。

inline.py 直接导入 check.py 的 classify()，两者对“本地引用”的判断是同一个函数：inline.py 要内联的，正是 check.py 会报 ✗ 的那一类。外部 URL inline.py 不碰，留给 check.py 报告。

$ python3 scripts/inline.py demo/chart.html
· inlined vendor/chart.umd.min.js (209 kB)
✓ demo/chart.html (209 kB)
$ python3 scripts/inline.py demo/chart.html
· nothing local to inline
✓ demo/chart.html (209 kB)
$ python3 scripts/inline.py demo/broken.html -o demo/broken-inlined.html
✗ cannot find 'logo.png' next to the page or in the skill's assets/
nothing written

第一次把 Chart.js 写进页面；第二次运行时已经没有本地引用，文件不变，这就是文件头说的“对自己的输出再跑一次，什么都不改”。第三次缺 logo.png，退出码 1，没有写出任何文件。

调研时验证过：Chart.js 和 uPlot 内联进一个 262 KB 的文件，断网用 file:// 打开，两个图表都能画出来。

上限：标签是用正则表达式改写的，手写页面够用；属性值里含 >，或者标签被注释掉时，可能要手工内联。真遇到了再换成正经的分词器。

出处scripts/inline.py 文件头说明（含「Ceiling」）和 Inliner 类；references/charts.md「Pick the tool」；docs/research.md「图表库内联的体积」

check.py：先扫标签，再断网打开

静态扫描保证文件里没有向外的引用；Chrome 检查在断网条件下真的打开页面，抓住偷偷发出的请求、脚本错误和横向溢出；截图块把剩下的问题交给 agent 用眼睛核对。“不引用任何外部资源”的契约和“解析后扫描”的做法，借自 warpdotdev/common-skills 的 readout。

静态扫描：不开浏览器

用 Python 标准库的 html.parser 逐个读标签，检查每个会被加载的引用。

  • 检查的位置：script src、link href，img 和 source 的 src、srcset，video 的 src、poster，audio、track、iframe、embed、input 的 src，object data，SVG image、use、feImage 的 href；还有 <style> 和 style="" 里的 url() 与 @import。
  • 以 #、data:、blob:、about: 开头的算在文件里。以 http:、https:、// 开头的报 ✗“loads … from the network”。其余的相对路径是单独的文件，报 ✗“is a separate file; inline it”。
  • 向外的 <a href> 只计数（·），页面不靠它们渲染；指向本地文件的 <a href> 报 !，因为对方没有那个文件。
  • 缺 <!doctype html>、<meta charset>、<meta name=viewport> 或 <title>，各报一条 !。

断网渲染：真的打开它

  • 用 --remote-debugging-pipe 启动本机的无头 Chrome（也认 Chromium、Edge，或环境变量 AWESOME_HTML_CHROME 指定的程序），每次用新的临时 profile。DevTools 协议走 3 号和 4 号文件描述符，所以只在 macOS 和 Linux 上跑。
  • --host-resolver-rules="MAP * ~NOTFOUND" 让所有域名都解析失败，同时不走代理。页面想联网也连不上，但它发出的请求会被记下来。
  • 页面本身和每个 --fragment，各在 400 和 1280 两种宽度、浅色和深色两种配色下打开，共 4 次。窗口高 900px；宽度小于 600 时按手机模拟。
  • 每次都用 file:// 打开，等 load 事件、字体加载完、再过一帧加 300ms，然后跑一段布局探针，再截图。
  • 记下：离开文件的请求（file:、data:、blob:、about:、chrome:、devtools: 以外的地址）、JS 异常、console.error、浏览器错误日志、横向滚动（并点名最宽的元素）、.slide 里溢出的内容、被 overflow: hidden 或 clip 裁掉的内容（text-overflow: ellipsis 除外），以及自己横向滚动的盒子。

截图块：能按原尺寸读

每次渲染按 1200px 高切成 PNG。TILE_HEIGHT 的注释给了理由：够高，读得下去；又不会高到被看图软件缩小。SKILL.md 的说法是“so they can be read at full size”。

只有一块时文件名是 page-400-light.png，多块时是 page-400-light-1.png、page-400-light-2.png……；--fragment 的渲染用 fragment 名代替 page，并转成安全的文件名。每次渲染最多 15 块，更长的页面只截顶部并报一条 !，建议拆页或用 --fragment 分段渲染。但对普通的滚动页面，fragment 只是滚到锚点，截图仍从顶部截起：本页实测时，带和不带 fragment 的两组截图逐字节相同。所以长页面要拆开或写短。截图默认放进新建的临时目录 awesome-html-shots-*，--shots 可以指定位置。

✗、!、· 三个级别

每条渲染发现的末尾用方括号写出它出现在哪几次渲染里，四次都有时写 [every render]。

标记意思会触发它的情况
✗ 问题 必须修。有任何一条，退出码就是 1；渲染中途失败时是 2。 静态：从网络加载、没内联的本地文件。渲染：离开文件的请求、JS 异常、console.error、浏览器错误、横向滚动、幻灯片内容被裁。
! 警告 不改变退出码，但要在截图里确认。 缺 doctype、charset、viewport 或 title；链接指向本地文件；内容被 overflow: hidden 裁掉；页面超过 15 块，只截了顶部；没找到 Chrome，或系统不是 macOS、Linux，渲染被跳过。
· 说明 不用修，知道就行。 外链数量；盒子在自己内部滚动（截图里滚动条是隐藏的）；用的是哪个 Chrome、截图放在哪；用 --no-browser 跳过了渲染；最后一行提醒打开每一块截图。

没有 ✗ 时会打印两行 ✓：“static: nothing loads from outside the file”和“browser: no outside requests, no JS errors, no sideways scroll”。退出码 0 表示干净，1 表示有 ✗，2 表示用法或环境出错，例如渲染中途失败。

track.py：看板从 Markdown 生成

进度只记在仓库里的 Markdown 文件中，HTML 看板是从它生成的只读页面，这是 owner 定下的规则。track.py 负责这次转换，所以看板不会和记录分叉。这个仓库自己的 examples/progress.html 就是从 docs/wip/html-skill.md 生成的。

它只读源文件里的这几部分，其它段落（目标、笔记、链接）都忽略：

# 项目名（WIP）
更新：2026-10-06
## 已定决策
| 日期 | 决策 | 谁定的 |
## 进度
### 里程碑名
- [完成] 条目。证据：提交 abc1234
## 还没做
- 有意不做或推迟的事
  • 状态只有五种：done、doing、blocked、todo、dropped，中文写作 完成、进行中、阻塞、待办、已放弃。“证据：”或“Evidence:”后面的文字成为条目的备注。标题里的“（WIP）”会被去掉。
  • 未知状态、写在 ### 里程碑之外的条目，或者一个里程碑都没有，都报 ✗ 并给出行号，什么都不写。
  • 第一次运行从 assets/track.html 复制出页面，并按内容选 lang：汉字至少占字母总数的五分之一时用 zh-CN，--lang 可以覆盖。之后每次只替换 #track-data 数据块和 <title>，模板上的改动会保留。
  • 一句话摘要是判断，不是数据，所以由 --summary 传入；不传就沿用页面上已有的那句。
  • updated 取自源文件的“更新：”行，没有就用当天日期；source 记录源文件相对仓库根目录的路径。JSON 里的 </ 写成 <\/，免得提前结束 <script>。
  • 完成了却没写证据、阻塞了却没说被什么阻塞的条目，各报一条 !。证据不能编，缺口要报告给用户。

为什么不用 Artifact 或 answer-me-with-html

要把页面作为一个文件交给合作方，就用 awesome-html。Claude 的 Artifact 页面跟 Claude 账号绑定，打包不出来；answer-me-with-html 的页面能离线，但组件和主题是固定的，也没有真正的图表。

README 的「Why」把这件事说成三句：托管的 artifact 页面留在账号里，没法把文件交给合作方；模板渲染器能产出文件，但每一页都长得一样；awesome-html 保留设计上的约束，自由地写页面，然后证明这个文件能独立存在。

不用 Artifact 是 owner 的决定（docs/wip/html-skill.md 决策表第一条），但它仍是质量标杆：目标写的是“质量对标内置 artifact 页面”。内置的 artifact 设计指南没有许可文件，所以只借原则、用自己的话重写。

方案能不能作为一个文件发给合作方外观和图表现状
Claude Artifact ✗ 不能：页面跟 Claude 账号绑定，打包不出来 质量标杆：awesome-html 的目标是对标内置 artifact 页面 owner 已决定不再用它生成或发布 HTML
answer-me-with-html ✓ 能：它的页面本来就能离线 组件和主题都是固定的，没有真正的图表 暂时并存；awesome-html v1 跑通后替换它，停用要等 owner 授权
awesome-html ✓ 能：一个 .html，inline.py 写进资源，check.py 验证 每页按主题自定 :root token；图表用手写 SVG，或内置的 Chart.js 4.5.1 v1 的脚本、参考文档和模板已完成；复测和上线还是待办

出处README.md「Why」；docs/wip/html-skill.md「目标」、决策表第 1、4 条、「上线」；docs/research.md「不采用」和「采用或借鉴」最后一行；references/design.md；references/charts.md「Pick the tool」；NOTICE

边界和还没做的事

  • 渲染需要 macOS 或 Linux，以及本机的 Chrome、Chromium 或 Edge；Windows 上只跑静态扫描。没有浏览器时，check.py 会打印一条 ! 说明页面没有渲染。
  • check.py 只渲染页面加载后的样子，不会点击，toast、加载中这类瞬时状态截不到。原型的每个界面和状态要用 --fragment 逐个渲染。
  • 每次渲染最多 15 块截图，更长的页面只截顶部；对普通滚动页面，--fragment 截不到下面的部分。
  • inline.py 用正则改写标签，遇到属性值里的 > 或被注释掉的标签，可能要手工内联。
  • 还没有配色校验器（对比度和色盲区分度），参考文档里只有文字规则。
  • 还没有幻灯片的实测样例，只有模板和自动化测试。
